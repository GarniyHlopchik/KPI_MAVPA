## Сутності

> Зауважу, що в полях не записано foreign ключі, адже вони є скоріше фізичною деталлю реалізації бд, ніж логічним елементом

# Person

Спільні дані для звичайних юзерів та модераторів. Містить поля id (UUID, primary key), login, password_hash, username

# User

Звичайний користувач. Поле id (primary key)

# Moderator

Модератор. Поле id (primary key)

> Обидва цих Entity на даний момент не потребують жодних власних полів окрім ключа. Усі інші будуть foreign keys, що є деталлю реалізації

# Thread

Гілка, що містить повідомлення. Має атрибути id, is_active, name

# Message

Повідомлення. Атрибути: id, sender_status (registered, verified, not_verified), text, username, tripcode

# PrivateGroup

Сутність для приватних повідомлень та груп. Може мати в собі два чи більше зареєстрованих користувача. Недоступні для модераторів. Поле id 

## Зв'язки

# Person-User-Moderator

Для кожного Person існує або відповідний User або відповідний Moderator. Отже на лише одного Person приходиться нуль чи один User; на лише одного Person приходиться нуль чи один Moderator (Foreign key до Person на User та Moderator)

# Thread-User-Message

Thread має власника, та сама людина може мати кілька гілок, зв'язок нуль чи багато до тільки одного. Гілка містить нуль або багато повідомлень - тільки один до нуля або багатьох. Повідомлення при цьому можуть мати відповідного юзера, а можуть не мати (анонімні чи юзернейм та тріпкод) - нуль або багато до нуля чи одного. 

# PrivateGroup-User-Message

PrivateGroup має кілька юзерів (2 чи більше), які до неї входять, зв'язок нуль чи багато до 2 чи більше. Група містить нуль або багато повідомлень - тільки один до нуля або багатьох.
